# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- Baseline import of the HoTH iOS app (built before Oct 26, 2026): live-camera reporting, bilingual voice intake, explained priority with safety floors, neighbourhood feed and map, confirmations, moderated comments, nearby alerts, crew fix verification, on-device face and plate blur, and the offline eval harness.
- `MetaModelClient.transcribe(wav:model:languageHint:keywords:)` for Muse Voice Transcribe file mode (multipart `request` JSON + `audio` WAV, PUSH_TO_TALK, language and keyword biasing).
- `MetaModelClient.segment(image:concept:model:)` for SAM 3.1 concept segmentation, with `SAMOutputParser` for its box/mask token text (boxes in source pixels, optional confidence, masks kept encoded).
- `HazardSegmenter` outlines a report category with SAM 3.1: one noun phrase per category from prompts.json `segment_concepts` (none for `other` / `not_an_issue`), a 20 s budget (`Failure.timedOut`), and `SegmentSelection` keeping up to 3 boxes by score while dropping specks, low scores and boxes whose `w`/`h` aspect does not match the sent JPEG. `OverlayGeometry` maps 0...1 boxes into aspect-fit and aspect-fill views.
- `WAVAudio.canonicalPCM16(_:)` rewrites a recorded WAV to a 44-byte-header mono 16-bit PCM file (drops padding chunks such as `FLLR`) and rejects formats Muse Voice Transcribe refuses.
- Push-to-talk voice (`PushToTalkModel`): hold or tap the mic, record 24 kHz mono 16-bit WAV with `AVAudioRecorder` (temp file deleted after upload), transcribe with Muse Voice Transcribe, and read each reply aloud with `AVSpeechSynthesizer` in the reply's language (ar-SA / en-US). Mic denial and recording or transcription errors fall back to typing. The audio session (`.playAndRecord` + `.defaultToSpeaker`) is set up on the first spoken reply or press, so the opening reply is not muted by the silent switch.
- Report flow outlines the hazard with SAM 3.1: after a live Muse Spark analysis, the same JPEG goes to SAM with the category's concept, and up to 3 boxes draw in (dashed, teal glow) over the analysis photo and the ticket thumbnail, with an "Outlined by SAM 3.1" chip (en + ar). SAM runs alongside priority and dedup, is cancelled on retake or merge, and any failure or timeout just leaves no overlay. Offline canned analyses and UI tests make no SAM call, and no SAM results are bundled.
- Crew fix check shows SAM 3.1 "what's left" boxes on a rejected live verdict: SAM runs on the exact after JPEG the verifier saw with the report's concept, its boxes replace Muse Spark's `remaining_issues` when it finds something (with the SAM chip), and a timeout, error or zero matches keeps Spark's boxes. Canned demo verdicts make no SAM call.
- `MetaModelClient.respond(model:input:tools:schema:)` sends Muse Spark function tools over the Responses API with stateless encrypted reasoning replay (`store: false`, `include: ["reasoning.encrypted_content"]`), and `ToolLoop.run` pairs every `function_call` with a `function_call_output`, replays each round's output verbatim, caps tool rounds (default 4) and decodes the final json_schema answer.
- `HazardSegmenter.outline(jpegData:concept:)` outlines a free-form concept (for the intake agent's `segment_hazard` tool); `sanitizedConcept` refuses anything but a short noun phrase (at most 4 words, 40 characters, letters, digits, spaces, `-` and `'`) without a network call.
- prompts.json `intake_agent` (decoded as `Prompts.intakeAgent`): the intake agent's tool rules, `max_tool_rounds` (4) and three function tools, `find_nearby_reports(radius_m)`, `segment_hazard(concept)` and `get_place_context()`, with no range keywords in their schemas.
- Agentic interview: with a Meta key, each chat turn is a Muse Spark tool loop. The agent checks open reports nearby on the phone and can offer "a neighbour already reported this, confirm it instead?", which merges into that report like "I saw it too" (only ids the tool returned, only open reports in range). It reads nearby places and the scene, and can outline another hazard with SAM 3.1 (sanitized concept, one call per concept). While it works the typing line says what it is checking (en + ar). A 400 or an undecodable turn switches tools off for the session and retries single-turn, a round limit finishes that turn single-turn with the tool results, and key, billing, rate-limit or network errors use the offline chat as before. The agent has no priority output, so `PriorityAgent` floors stay authoritative. Settings has an "Interview agent tools" toggle (default on); UI tests and keyless runs stay on the local chat.
- `LiveMetaTests`: opt-in live checks of every Meta integration through the real client (`GET /v1/models`, Muse Spark vision, fix verify, duplicate judge, moderation, a tool-calling round trip, Muse Voice Transcribe on `say`-generated English and Arabic WAVs, SAM 3.1 boxes). Skipped unless `META_API_KEY` is set; each call logs its latency.
- Feed cards read like social posts: reporter header (initials avatar, "Anonymous neighbour" or "You", relative time, place, distance), title and summary, full-width photo, priority badge, category chip and vote, a "7 neighbours saw this · 3 comments" row, and an action bar with I saw it too (now also on the card), Comment (opens the case scrolled to comments) and Share (title, summary and place only). `SightingConfirmation` holds the confirm logic shared with the case detail (en + ar).
- Onboarding has a text-only "Powered by Meta AI" page naming Muse Spark 1.3 (photo understanding, interview agent, fix checks, comment moderation), Muse Voice Transcribe (Arabic or English voice to text) and SAM 3.1 (hazard outline), and Settings' AI models card lists the same models (en + ar, model names in Latin script). The permission primer stays on the last page.
- Settings "Reset app" (with confirmation): `AppResetter` checks the bundled seed, deletes every SwiftData record and re-seeds the demo community like first launch, removes all `hoth.` settings (demo mode, role, model overrides, language, onboarding flag, confirmations, alert state), deletes report and fix photos in Documents and voice temp files, and cancels pending and delivered notifications. "Reset app and remove Meta API key" also deletes the key (shown only when a Keychain key is saved). The app rebuilds in place and onboarding shows again, no relaunch needed; failures leave a notice in Settings (en + ar). The existing "Reset demo community" stays.
- DEBUG-only demo-film capture mode (`HOTH_DEMO_CAPTURE=1`): in-memory store reseeded every launch, confirmations and the alert timestamp cleared at launch (`HOTH_CAPTURE_ONBOARDING=1` also clears the onboarding flag), optional `HOTH_CAPTURE_SKIP_SPLASH=1`. It never implies `HOTH_UITEST`, so SAM, push-to-talk, the intake agent, moderation, splash and alerts stay live. Release builds are unchanged.
- DEBUG-only `FileVoiceRecorder`: in capture mode push-to-talk plays a WAV playlist from `HOTH_PTT_WAV_DIR` (or `Documents/ptt`) instead of the microphone, in name order, and hands `PushToTalkModel` a temp copy so the real clip goes to Muse Voice Transcribe. The directory is validated (absolute, existing, regular `.wav` files only, no symlinks, 8 MB cap, mono 16-bit 16/24 kHz, at least 400 ms); a bad playlist fails the turn visibly instead of falling back to the host microphone. A clip whose size cannot be read is rejected, and the temp copy is checked again before it is handed over, so a clip changed after loading never reaches Meta. The orb follows each clip's real loudness.
- DEBUG-only intake-agent tool-call log: each call goes to `os.Logger` as one line (`find_nearby_reports radius_m=150 -> 0 results`), and in capture mode it is also appended with its arguments, output and duration as JSON lines to `<HOTH_CAPTURE_LOG_DIR>/hoth_app_log.jsonl` (else `Documents/capture`), next to a `capture_launch` record. The log file is never written through a symlink, quoted values in the one-line form escape `"` and `\`, and the `os.Logger` line is private.
- Accessibility ids for scripted capture: `caseConfirmButton`, `caseVoteButton`, `commentField`, `commentSendButton`, `commentPending`, `resetDemoButton`, `resetConfirmButton`, `heroLevelTitle`, `heroPoints`, `routedToTeam`, `quickReply_<n>`, `chatBubble_assistant` / `chatBubble_resident`.
- `DemoCaptureUITests`: the demo film's scenes (`test00_WarmUpNotifications`, `test02_SpringRiderVoiceAR`, `test06_NeighbourAlertConfirmCommentAR`, `test08_CrewFixCheck`), live and skipped unless `TEST_RUNNER_DEMO_CAPTURE=1`, with `beat()`, `mark()` (JSON lines to `TEST_RUNNER_CAPTURE_LOG`, including tap positions), `holdToTalk()` and a notification-permission monitor. C1 first checks that the app's `capture_launch` record lists the same playlist with no `ptt_error`, and the interview stops with a failure (never spins) if the safety sheet will not dismiss or the turns run past the clip budget.
- `UploadRedactionTests`: hermetic checks that every image in every Meta request (vision, duplicate judge, SAM, `segment_hazard`, fix check before/after) is an output of the on-device redactor and never the original's bytes, that a failed redaction makes no request, that the real blur leaves a synthetic plate unreadable at the same pixel size, and that the 10 s timeout fails closed.
- `LiveRedactedVisionTests` (opt-in, `TEST_RUNNER_HOTH_LIVE_REDACTED=1` + `TEST_RUNNER_META_API_KEY`): runs the spring rider demo photo through the app's blurred upload path N times (`TEST_RUNNER_HOTH_LIVE_RUNS`, default 5) and appends per-run results to `TEST_RUNNER_HOTH_LIVE_OUT`.
- `DemoCaptureUITests` take `TEST_RUNNER_CAPTURE_LANG=en|ar` for C1, C2 and C3 (defaults: C1/C2 Arabic, C3 English). Seed titles, the crew title and the C2 comment follow the language (English comment: "Careful — the cabinet door is open and the wires are bare, right by the school walkway."), `TEST_RUNNER_CAPTURE_COMMENT` overrides it, and the launch mark records the language. Method names are unchanged.

### Changed
- Logo and app icon recoloured to the blue theme: the hand-and-house shield is #0866FF, the leaves a light cyan (#36C5F0) and the paper a cool grey-white (#F5F7FA), same shapes and paper texture. `tools/brand/recolor_logo.py` regenerates both PNGs deterministically from the saved coral originals, and the logo shadow is blue-tinted instead of warm.
- Social-network theme: blue accent (#0866FF light, #2D88FF dark) on cool neutral backgrounds and white cards, system sans instead of serif for display and titles, smaller card radius (14) with hairlines and one faint shadow, blue-tinted selected filter chips. The accent and launch-background colour sets follow.
- Muse Spark structured calls (vision, duplicate judge, fix check, moderation, single-turn chat) now send `store: false`, so Meta does not keep these responses for later retrieval (the Responses API defaults to `store: true`). The tool loop already did.
- The interview offers push-to-talk inside the chat when a Meta key is set: the orb shows listening, transcribing, thinking and speaking, "Type instead" and a mic button switch modes without losing the conversation, and "Start interview with voice" picks the starting mode (UI tests stay on the local typed chat). The Talk/Type picker is gone, and the Settings caption and en + ar strings describe the new voice.
- AI client is now `MetaModelClient` on the Meta Model API (`https://api.meta.ai/v1`): 60 s timeout, configurable reasoning effort (default low), no image `detail`, provider-neutral `ModelAPIError`, and error bodies scrubbed of `LLM_…` keys.
- prompts.json targets Meta models (`muse-spark-1.3` for vision and text, `muse-voice-transcribe-1.0`, `sam-3.1`). Schemas drop `minimum`/`maximum`/`maxItems` (clamped in Swift) and boxes use Muse Spark's 0-1000 grid, normalized once in `NormalizedBox`.
- App wiring and copy name Meta: the key is stored under Keychain service `HoTH.MetaKey` (DEBUG simulator falls back to `META_API_KEY`), Settings says "Meta Model API key" and Muse Spark with a new text model override for chat and moderation, and privacy copy (en + ar) says photos go to Meta's Muse Spark model. UI tests read `TEST_RUNNER_META_API_KEY`.
- Eval harness calls the Meta Model API (`META_API_KEY`, 60 s app timeout, reasoning effort low, no image `detail`) and prices runs at Muse Spark 1.3 Standard rates ($1.25 in, $0.15 cached in, $4.25 out per 1M tokens).

The intake agent still gets the English labels. Smoke eval unchanged (3/3 category, fix 1/1).
- Arabic UI showed the SAM 3.1 concept in English next to «حدّده SAM 3.1» (analysis card and crew fix check, including the fix-check box tags). prompts.json `segment_concepts_ar` gives each category concept an Arabic display name (`Prompts.segmentConceptDisplayName`); SAM still gets the English concept, and free-form agent concepts show their English text.
- Arabic "Why this priority" showed the safety floor in English ("CRITICAL — child safety"). Floors carry Arabic labels and `PriorityDecision` has `floorAppliedEN` / `floorAppliedAR`.
- The analysis card's trust chips wrap instead of scrolling sideways, so the "Outlined by SAM 3.1" chip no longer runs off-screen (Arabic, iPhone 17 Pro); `ReportWrapLayout` lets an over-wide chip wrap its text.
- Demo capture C2: in DEBUG capture mode the neighbour-alert notification goes to Notification Centre without a foreground banner, so it no longer covers the in-app "Demo" alert banner. Release behaviour unchanged.
- `DemoCaptureUITests` (first live capture run): ids that match more than one element (the CRITICAL badge did) are resolved with `firstMatch`, so logging a tap position no longer fails the scene. The interview no longer stalls when the simulator's speech synthesizer stays on "Speaking…" without ever finishing: after a read-out allowance (about 12 characters a second plus 2 s, 4–25 s) the next hold uses the app's own barge-in, and the test logs `tts_barge_in`.
- Distances are always metric ("233 m", "1.3 km") whatever the device region: the feed card, map card and merged-duplicate screen showed feet (e.g. "763 ft") on a US-region device or with the in-app English override. - Feed and Settings scroll content no longer runs under the status bar clock (page-colour backdrop behind the status bar).
- A `find_nearby_reports` call with a huge `radius_m` (such as 1e30) no longer crashes the app: the radius is clamped to 10...500 m before it becomes an `Int`.
- Leaving the interview cancels the chat turn in flight: a late Muse Spark reply no longer adds bubbles, falls back to the offline chat, or finishes the report. - Switching to typing (or leaving the interview) while a voice turn is being transcribed no longer shows "Couldn't turn your voice into text", and a transcript that comes back for an abandoned turn is dropped instead of being sent into a newer turn.
- A cancelled Meta request (task cancelled or `URLError.cancelled`) now throws `CancellationError` instead of `ModelAPIError.network`, so callers can drop abandoned work silently; timeouts stay network errors. `ToolLoop` also stops between tool rounds once cancelled.
- Muse Spark's hazard boxes on the analysis photo are laid out left-to-right in Arabic too, like the SAM layer and the fix-check boxes, so the two never disagree under RTL.
- The repair photo is made upright and downsized to 1024 px before the fix check, so boxes from the model land on the shown image (camera shots arrive `.right`-oriented at full resolution).
- Arabic UI showed the fix check's "what's left" labels in English. The fix-check schema now asks for `label_ar` per remaining issue (decoded as `RemainingIssue.labelAR`, optional for older responses), `FixVerdict.Region` carries it, and the canned "Unfilled gravel" has an Arabic name («حصى غير مردوم»). SAM regions keep the Arabic concept name.

### Security
- Photos are blurred on the phone before they are sent to Meta, not only before posting. Vision, SAM 3.1, the duplicate judge (new photo and the existing report's public photo, blurred again on the phone), the intake agent's `segment_hazard` and the fix check (before and after) all receive the `FaceAndPlateBlur` output, and the same blur is reused for the posted photo and the saved fix photo. Fail-safe: if the blur fails or takes longer than 10 s (`FaceAndPlateBlur.uploadTimeout`), nothing is sent; the report shows "I couldn't blur faces and number plates on this photo, so it wasn't sent. Please take it again." and the fix check "Couldn't blur faces and number plates on these photos, so nothing was sent." (en + ar). Offline canned demo analyses send nothing, so they skip the gate. Privacy copy in Settings, onboarding, the capture disclosure and the ticket says so (en + ar). The eval harness still sends unblurred dataset images (Apple Vision is not available to the Python harness).
